PASSO 2: CONFIGURAÇÃO DO SUPABASE (SUBSTITUI TURSO + CLERK)
========================================================================
1. Crie um projeto no Supabase.
2. No editor SQL do Supabase, ative a extensão 'uuid-ossp'.
3. Crie as tabelas mantendo a coluna 'tenant_id' (ou 'restaurant_id') em TODAS as tabelas.
   Isso é vital para isolar os dados dos 5 clientes.

Tabelas Sugeridas:
- profiles (id, name, role, restaurant_id)
- products (id, name, sku, stock_qty, restaurant_id)
- shifts (id, date, start_time, end_time, restaurant_id)
- schedule_assignments (id, shift_id, employee_id, restaurant_id)

4. IMPORTANTE: Ative Row Level Security (RLS) em todas as tabelas.
   Política de exemplo (apenas quem é daquele restaurante vê os dados):
   CREATE POLICY "Isolate Tenant Data" ON products
   FOR ALL USING (auth.uid() IN (SELECT id FROM profiles WHERE restaurant_id = products.restaurant_id));

PASSO 4: MIGRAÇÃO DA LÓGICA (Laravel -> Next.js Server Actions)
========================================================================
Você não precisa de rotas API (`/api/...`) para tudo. Use **Server Actions**.
Elas rodam no servidor, têm acesso ao DB e são seguras.

Exemplo de como transformar um Controller Laravel em Server Action:

// src/lib/services/estoque-service.ts
'use server' // Isso define que roda no servidor (Backend)
import { createClient } from '@/lib/supabase/server'
import { revalidatePath } from 'next/cache'

export async function atualizarEstoque(produtoId: string, novaQtd: number) {
  const supabase = createClient()
  
  // 1. Verifica permissão (o usuário logado pertence ao restaurante?)
  const { data: user } = await supabase.auth.getUser()
  if (!user) throw new Error('Não autorizado')

  // 2. Atualiza no DB
  const { error } = await supabase
    .from('products')
    .update({ stock_qty: novaQtd })
    .eq('id', produtoId)
    .eq('restaurant_id', user.restaurant_id) // Segurança extra

  if (error) throw new Error(error.message)

  // 3. Atualiza a tela do cliente automaticamente
  revalidatePath('/dashboard/estoque')
  return { success: true }
}

PASSO 5: RESOLVENDO A DOR DE CABEÇA (AUXILIADOR DE ESCALAS)
========================================================================
Como a lógica de escala é complexa, não a deixe espalhada nos componentes.
Centralize no diretório `src/lib/services/escala-service.ts`.

Estratégia para o algoritmo de escalas:
1. Crie uma função pura em TypeScript que recebe: [Lista de Funcionários, Regras, Dias do Mês].
2. Essa função roda no Servidor (Server Action) quando o gerente clica em "Gerar Escala".
3. O servidor processa, salva no banco e retorna a sugestão.
4. O Frontend apenas exibe o resultado.
   -> Isso evita travar o navegador do usuário com cálculos pesados.

Dica: Use bibliotecas leves de validação de datas como 'date-fns' para evitar conflitos de horários.

========================================================================
PASSO 6: IMPRESSÃO DE ETIQUETAS
========================================================================
Não gere PDF no servidor (consome memória). Gere no Cliente.
1. Use a biblioteca `react-to-print` ou `jspdf`.
2. Crie um componente visual `<Etiqueta produto={produto} />`.
3. Quando o usuário clicar em "Imprimir", esse componente é renderizado oculto e enviado para a impressora térmica.
4. Use CSS `@media print` para formatar o tamanho exato da etiqueta (ex: 50mm x 30mm).

========================================================================
PASSO 7: LIMITES DO FREE TIER (CONTROLE DE CUSTO)
========================================================================
Para manter 5 clientes no GRÁTIS:
1. Supabase: Limite de 500MB de banco de dados e 50k usuários ativos/mês.
   -> Para 5 restaurantes, isso é mais que suficiente (cada um terá ~10-20 funcionários).
2. Vercel: Limite de 100GB de banda e funções serverless gratuitas.
   -> O Next.js é estático na maior parte, consumindo pouca banda.

ATENÇÃO:
- Não armazene imagens pesadas no Supabase Storage se não for necessário.
- Faça "Soft Delete" (apenas marca como deletado) para não estourar o limite de linhas se o banco encher (embora 500MB aceite milhões de linhas de texto).
